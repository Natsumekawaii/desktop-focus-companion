# Desktop Focus Companion Internationalization Guide

Desktop Focus Companion currently supports these interface languages:

- Simplified Chinese (`zh-CN`)
- English (`en-US`, the compatibility default when a legacy settings file has no language field)

## Implementation

The internationalization entry point is `app/i18n/translator.py`. `LocalizationManager` loads language catalogs, owns the current language, sets Qt's default `QLocale`, and notifies every open window through `language_changed` so it can retranslate immediately. Components obtain text with `tr("semantic.key")`; they do not branch directly on language codes.

Dates, months, and weekdays are formatted through `format_date`, `format_datetime`, `format_month_year`, `format_time`, and `format_weekday` in the same module. Compact durations use the shared formatter in `app/timer/formatting.py` and localized catalog entries.

The selected language is stored in `settings.json` under the user data directory:

```json
{
  "language": "en-US"
}
```

A language change first persists the setting atomically and then broadcasts the runtime update. At startup, the application loads this field before creating any window or showing a startup-error dialog. Legacy settings require no migration; a missing or invalid language code safely falls back to `en-US`.

## Translation resources

Central JSON catalogs are stored in:

```text
app/i18n/locales/
├── en-US.json
└── zh-CN.json
```

Both catalogs must contain exactly the same semantic keys. Their key sets are validated at startup; missing or extra keys are treated as development errors. The PyInstaller configuration copies the complete directory into packaged builds.

## Adding interface text

1. Add the same semantic key to every existing language JSON file, for example `dashboard.empty.no_sessions`.
2. Call `tr("dashboard.empty.no_sessions")` from the widget or controller.
3. Use named placeholders such as `{count}` for variable text; every language must use compatible placeholders.
4. Use explicit `.one` and `.other` keys for pluralized content, with business code selecting the semantic key from the quantity.
5. Set static window text in `retranslate_ui()` and connect it to `language_changed`.
6. Keep the raw values behind formatted dates, durations, and statistics so they can be reformatted when the language changes.
7. Never translate user-entered Focus Item names, Notes, or file names.

## Adding a language

For example, to add Japanese:

1. Copy `en-US.json` to `ja-JP.json` and translate every value.
2. Add `Language("ja-JP", "日本語")` to `SUPPORTED_LANGUAGES`.
3. Keep the catalog key sets identical and run the complete test suite.
4. Check Settings, Focus Panel, Dashboard, tables, dialogs, menus, and Tooltips at minimum and common window sizes.

The Settings selector, persistence layer, and packaging scripts require no changes; they derive their behavior from the supported-language list and catalog directory.
